# 2026-09-09：解析后长时间停留在 0/N 的修复

URL 填 `https://mineru.net` 即可。[官网文档](https://mineru.net/apiManage/docs)中的 `/api/v4/extract/task` 接收网络文件 URL，本地文件采用 `/api/v4/file-urls/batch` 上传。误填完整官网端点也会归一化到服务地址。

## 根因与修复

- 表格处理和等待模型响应期间没有进度，只有整段完成才更新。现显示表格 / 正文阶段与等待时间；等待提示仅更新界面，重复解析状态不刷日志。最终译文产生前禁用“打开结果”。
- 日期译为中文后，月份由英文变成数字，旧检查误判数值改变并拆批重试。现按有效日期比较，保留两位年份的原始含义，不猜测世纪；百分号空格、分辨率乘号及常见文字计数也做等价核对，真实数值改变仍会报告。
- 单个单元格出错曾连带重新请求同批合格内容。现在只重试不合格单元格。
- 没有一级标题的 MinerU 封面曾生成通用 `translated_…` 目录。现在采用原文件名，并继续寻找同指纹旧任务以保留缓存。检查规则更新会重新校验已有响应，不要求重新翻译全部内容。
- Word 导出补充 `mathsf`、`boldsymbol` 字体指令与 OCR 数字空格处理。有效 Markdown 数学指令不再直接判为 Word 格式错误；无法转换的指令继续列入报告。

## 验证

88 项本地 Windows 回归测试通过。用户授权使用真实 API 后，核对了 33 页 PDF 来源哈希、官网原任务 `done` 状态，并成功完成 8/8 段。输出 Word 含 11 张表格、29 张图片，无失败段落及缺失图片。

旧版复现使用 71 次模型请求，约 1131 秒，大量重试来自日期误判。修复后的恢复任务复用了已有译文，仅新增 4 次请求补齐缺失内容；随后禁止模型调用再次运行，0 次新请求正常导出。这是续跑验证，不能作为全新任务提速比例。

使用本机 Word 导出 PDF 并查看封面、表格目录和公式密集页。原解析中的少量 `overline` / `mathfrak` 字符及英文专名仍列为待检查项，没有猜测性改写。私人 PDF、翻译内容、API Key 和调试响应均不进入 Git。
