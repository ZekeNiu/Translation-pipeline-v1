# 长书翻译与复核使用及验收记录

## 使用方式

默认流程为选择文档、翻译、阅读成品、重点复核。重新启动 `run_gui.bat` 后使用新界面。

- **重点复核**：只列待处理问题，按完整性、数值、术语、翻译疑点排序；表格整体展示，点击黄色单元格编辑。可筛选章节、类别和处理状态，支持搜索、前后导航与批量确认明确选中的普通条目。
- **章节阅读**：关闭重点复核过滤，在连续阅读页浏览原译文、图片和图注，点击内容进入编辑。大列表每组 100 项，表格每组 40 行，保留合并单元格关系。
- **保存修订**：立即持久化，不调用模型，不重建整书。成品待更新时点击“更新成品”。生成使用固定快照；其他窗口在导出期间保存的新修订留待下一次导出。
- **AI 改译 / 补译**：产生请求。候选与现译分开，采用到编辑框后仍需保存；使用原任务服务、模型、温度与当前确认的术语。原页没有可靠定位时明确显示未定位。
- **确认与遗漏**：可确认保留、稍后处理、重新打开；疑似遗漏可以补译，也可填写无需恢复的依据。确认绑定当时的原译文和有效约束，内容变化后重新检查。
- **我的任务**：打开旧任务、导入或重新关联目录、继续解析或翻译、查看记录中的用量与空间。个人索引只记录位置与非密钥选项，任务目录保存实际数据。
- **清理**：只清理临时导出与未采用候选缓存。人工修订、原页摘录、历史成品、解析结果和翻译缓存保留，不自动清理。

HTML 报告增加本地搜索及类别筛选，数字问题展示原文缺失和现译新增的值。规则检查不等于完整语义审校；已确认专名也不成为无条件全书白名单。

## 长文解析和上下文

官方 API 的限制仍为每份 200 页、190,000,000 字节。本地和自建 API 的默认外部分片阈值为超过 256 页，目标 128 页，章节搜索范围 64—192 页。分片阈值与每片上限是不同参数；自建服务明确的硬限制另行设置。边界复制原始 PDF 页面，不降采样。

章节边界也核对接缝。补充页不直接拼入正文，只在位置、文本、表格结构及图片证据一致时采用其结构；不确定时保留主分片并报告。分片编号不代替全书页码。

本地 MinerU 3.4.5 通过 `--api-url` 共用本任务启动的服务，各片串行处理；内部处理窗口仍由 MinerU 管理。其他版本保留逐片 CLI 兼容路径。完成结果校验命中时不启动服务；取消或退出结束本任务拥有的进程树。服务与 CLI 原始日志保留在解析任务内。

自建服务识别现代健康检查与异步任务协议，也兼容旧同步入口。提交前保存状态，取得任务编号后立即落盘；响应未知且没有任务编号时，不自动重复上传。核实服务端后可在高级设置允许下一次重交，该选择不持久保存。

新翻译任务使用完整相邻句段与章节路径；表格批次附带相关表名、行列标题与单元格编号，缓存包含实际上下文。默认 32,768 是应用保守工作预算，不是对模型最大窗口的声明；估算使用 UTF-8 字节数，包含提示、术语、上下文和输出预留，超限在发送前阻止。可通过高级设置或 CLI `--context-budget` 调整。

旧任务继续使用其已验证分段和旧请求约束，升级不会自动整书重译。新内容编号与请求分段分离；旧编号仅在完整有序原文块能对应时沿用，不猜测迁移人工修订。

`run()` 仍返回 Markdown 和 DOCX 路径。旧 `save_edit()`、`confirm_unit()`、`adopt_omission()` 调用默认保持保存并导出的行为；新界面传入 `export=False`，集中调用 `reexport()`。用量日志仅记录返回用量、耗时和阶段，不记录密钥或提示词，不虚构金额。

## 验收证据

### 自动与界面检查

- Windows Python 3.11 和 3.14：152 项回归测试通过。功能提交 `54ed78a` 的 [GitHub Actions](https://github.com/ZekeNiu/Translation-pipeline-v1/actions/runs/35057325170) 两个版本均通过。
- 新增覆盖：保存与确认无模型／无导出、导出中断整组恢复、导出期间的新修订不混入快照、遗漏判定撤销、表格聚合、上下文缓存隔离、稳定编号、千页 PDF 覆盖与章节接缝、分片选择性续跑、未知提交不重传、现代 API 图片与位置、密钥不进入任务索引、清理保护人工记录与原页。
- 一万单元本机实测：索引 0.64 秒；窗口加载 0.71 秒；搜索含 200ms 延迟为 0.22 秒；切换 0.014 秒；保存 0.081 秒。复现：`python tests/long_book_acceptance.py --gui`。这些是本机测量，不保证其他设备相同。
- 本地真实报告：140 个上层单元、696 个单元格、5 个疑似遗漏；原来的 831 条平铺列表改为 17 个问题分组，仍覆盖 27 个待核对点。未自动采用任何遗漏候选。
- 真实报告重新导出时拦截模型调用；Markdown 哈希不变。通过原生 Microsoft Word 渲染 PDF，28 页逐页文字均与上一版相同，并检查全部页面及复核窗口截图。测试产物留在被忽略的 `tests/.artifacts`。

### 本地 MinerU 和服务实测

四页合成学术 PDF，GPU hybrid-engine：首次整份解析 65.99 秒；分成两个正文片和一个接缝片、共用一次服务启动，36.92 秒；校验缓存续跑 0.036 秒。冷热启动条件不同，不能据此承诺长书加速比例。

重复内容使接缝无法唯一定位时，系统保留完整主结果并提示，没有自动删段。独立的当前版本自建 API 实测成功返回 Markdown、图片及 content list，随后命中缓存且未重新提交。任务结束后核查没有遗留本次 MinerU 服务。

另一次带资源采样的相同样例实测：整份 58.94 秒、分片 47.82 秒；整机 GPU 显存观测峰值分别为 9308MiB 与 8688MiB，包含桌面等其他进程占用，并非该任务独占显存。两种结果规范化后的正文及表格行内容一致。短样例只能验证运行与接缝行为，不能替代真实千页扫描书的完整质量评估。

### 小样本翻译用量

现有翻译服务处理同一合成短正文和两个表格词条：

| 术语状态 | 请求数 | 输入 tokens | 返回 total_tokens | 耗时 |
| --- | ---: | ---: | ---: | ---: |
| 关闭 | 2 | 504 | 799 | 3.43 秒 |
| 开启一个命中术语 | 2 | 543 | 992 | 3.21 秒 |

合计四次请求。生成与推理用量、服务时延有波动；不据此宣称长书费用降低。不上传真实文档用于此项测试。

回退建议使用独立目录：

```powershell
git worktree add ..\Translation-pipeline-rollback rollback/pre-long-book-ux-20260916
```

代码回退不删除任何任务、解析结果或词库。需要用旧代码打开旧状态时，先复制当前任务目录到新位置；将 `review-v1` 中四个公开成品放回副本根目录，其他旧记录放到副本 `_internal`，保留副本中的图片与缓存。仅在副本上使用旧代码；新版任务及新增修订保持原样。不要把整个开发历史强制推回旧提交。

仍需人工判断的内容包括解析遗漏是否真实、语义是否准确以及不确定接缝。导出仍为中文重排，不承诺与原 PDF 同页；本轮没有对真实报告执行全书重译。
